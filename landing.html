Built for the payment that goes wrong

Most integrations work on the happy path. Money goes missing on the other ones.

Forged callbacks

No callback is trusted

Redirects, IPNs and webhooks are claims. The package asks the gateway's own API, checks the amount and currency, and only then changes the payment.

Double fulfilment

Paid exactly once

The IPN and the customer's redirect often arrive together. Status changes are atomic, so PaymentCompleted fires once.

Timeouts

A timeout is not a failure

If the gateway doesn't answer, the payment stays pending and bdpaygate:sync settles it later. A customer who paid is never marked failed.

Retries

Retries can't double charge

Each retry is a new attempt with its own gateway id. If a customer pays two of them, you get PaymentDuplicated to refund, not a second order.

Late success

Failed can still become paid

When a gateway confirms the money moved after a failure was reported, the payment completes. A fake "cancelled" can't strand a paid order.

Logouts

Customers stay signed in

Gateways return customers with a cross-site POST that wipes Laravel sessions. The callback routes run without sessions, so nobody gets logged out at checkout.

What happens to every payment

The same steps for all 12 gateways. Nothing the browser sends can mark an order paid.

  1. You call charge()

    The package records a pending attempt with a fresh gateway id and returns the checkout URL to redirect to.

  2. The customer pays on the gateway's page

    bKash, Nagad, a card or a bank. Your app does nothing here.

  3. The gateway calls back, and is not believed

    The redirect or IPN only says which payment to check. Its status, amount and ids are ignored.

  4. The package asks the gateway's own API

    Validation, execute or status query, server to server. The answer must name this attempt, and the amount and currency must match.

  5. One atomic update, one event

    PaymentCompleted, PaymentFailed or PaymentCancelled fires once. If the gateway can't be reached, the payment stays pending for bdpaygate:sync.

The whole integration

Install, add your keys to .env, and write these.

use ByteMinus\BdPayGate\Facades\BdPayGate;
use ByteMinus\BdPayGate\Data\Customer;

$payment = BdPayGate::driver('bkash')->charge(
    amount: 1500,
    reference: 'ORD-1001',
    customer: new Customer(name: 'Rahim Uddin', phone: '01711000000'),
);

return redirect($payment->checkout_url);
use ByteMinus\BdPayGate\Events\PaymentCompleted;

// Fires once, only after the gateway confirmed the payment.
Event::listen(PaymentCompleted::class, function (PaymentCompleted $event) {
    Order::where('number', $event->payment->reference)
        ->first()
        ->markPaid($event->payment->gateway_transaction_id);
});
$result = BdPayGate::refund($payment, 500, 'Damaged item'); // partial
$result = BdPayGate::refund($payment);                        // everything left

$result->accepted; // the gateway took it
$result->pending;  // it settles later at the bank
// No network, no credentials.
$fake = BdPayGate::fake();

$payment = BdPayGate::charge(300, 'ORD-1', $customer);
$this->get($payment->checkout_url); // completes it like a real redirect

$fake->fail($payment);              // or drive it from code

Questions developers ask

Which Bangladeshi payment gateways does it support?

bKash, Nagad, SSLCommerz, Upay, ShurjoPay, aamarPay, PortPos (formerly PortWallet), PayStation, UddoktaPay, Moneybag, EPS and DGePay. Rocket, OK Wallet and CellFin work through SSLCommerz, ShurjoPay or aamarPay.

Which Laravel and PHP versions are supported?

Laravel 11, 12 and 13 on PHP 8.2 to 8.5. Laravel 13 needs PHP 8.3 or newer.

Can I refund a bKash payment from Laravel?

Yes. bKash supports full and partial refunds, up to 10 per transaction, and the package tracks the refunded amount. SSLCommerz, Upay and PortPos also have refund APIs. The other gateways only allow refunds from their merchant panel.

What happens if the customer closes the browser after paying?

The gateway's IPN still completes the payment, and bdpaygate:sync settles any payment whose callback never arrived. Do your fulfilment in a PaymentCompleted listener, not on the thank-you page.

Can I use two SSLCommerz stores in one app?

Yes. Each entry in the config is a separate gateway name with its own credentials, routes and payments, so two stores of the same gateway work side by side.

How do I test without real payments?

Use BdPayGate::fake() in your tests: no network and no credentials. For a real end-to-end check, use the gateway's sandbox keys in a local app.

Is there a Node.js, Next.js or Express version?

Yes. The npm package bdpaygate has the same gateways and verification, with adapters for Express, Next.js, NestJS, Fastify, Hono, Koa, Nuxt, SvelteKit, React Router, Astro and AdonisJS. It runs on Node.js 20.19+, Bun, Deno and Cloudflare Workers, and can share the payments table with the Laravel package.

Is it free?

Yes. BDPayGate is open source under the MIT license.
